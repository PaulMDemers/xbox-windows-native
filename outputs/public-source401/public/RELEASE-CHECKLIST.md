# Before a public release

- Finish per-file and linked-component license/provenance review. Do not switch
  the private forensic repository to public; this separate allowlist is the draft.
- Review all exported bytes, notices and author metadata. Preserve legitimate
  upstream attribution; omit local credentials, personal paths and private data.
- Confirm upstream commit availability from the recorded locations.
- Complete the installed HAL/network/input source inventory, portable compiler
  and launcher wrappers and toolchain provisioning. Rebuild the current combined
  stack twice from fresh output directories; explain differences and validate it.
- Validate the corrected create-only installer on a disposable owned fixture.
  A previous refusal of an occupied installation proves a guard, not installation.
- Keep resolution prerequisites, E/F destinations, rollback and1080i limitations
  explicit. Test recovery without overwriting the current console installation.
- Retain Ftdisk49 as a failed strict gate. A scoped demo result is not full-system
  qualification. Do not substitute emulator results for physical observations.
- Review the final source archive and proposed public identity before publishing.
  Existing private0.1.0/0.2.0 and rollback archives remain immutable.

The draft deliberately includes no compiled payload or automatic installer. Source
reconstruction success does not complete these release gates.
