# Integration boundary

The complete private texture source is a PROPOSAL, not a compiled xemu child.
x286_active has only a declaration there: a future one-shot worker must supply
stable owned storage. The host harness supplies a separate fresh object for each
modeled process fixture. This is not a runtime reset or rearm API.

Arm must derive selected live keys/identities/names/refcounts from the actual
complete locked proof after independent native allocation attestation. Four
4096byte texture/guard ranges, complete callback/surface bijection and immutable
UI/context/container closure remain required. Merely passing p285_arm is not
authorization. Refusal leaves normal rendering/destruction behavior unchanged.

before_destroy holds the gate only for a currently tracked old live scalar
identity, then snapshots scalar fields while the original argument is live.
after_destroy receives no binding pointer and cannot dereference it. The old
pre-decrement x269 hook remains unchanged. Actual completed-free records therefore
have a distinct meaning and cannot be inferred retrospectively for273/282.

Normal creation hook uses the actual binder unit and current cache key after the
original generate_texture return, with original refcount1. Independent context/
GL errors and source/pixel snapshots must still be checked. A new lifetime is
assigned even if pointer or GL name equals an old tombstone. Normal bound hooks
observe original refcount2 after actual guest work. Any unexpected new-generation
decrement before sealing refuses; the controlled four-texture protocol must not
silently omit or compress such an event.

Next worker needs FOUR immutable graphs: pre-unit, post-unit, post-cache-disposal
BEFORE guest resume, post-replacement. The third candidate graph must show old
cache owners and GL names actually absent; the last graph contains independently
observed replacements. Old273 requires same live generations and cannot validate
this protocol. Retain exact original283 counted LRU disposal, whole guard ranges,
fresh CPU epochs and same-transaction clocks, owner/context/fence/pending checks.

Acquired overall transaction state controls getters and resume. Snapshot/GL/file
errors and any partial mutation quarantine with exact masks, no rollback or
counter assignment. A closed gate or return from pb_busy is not GPU completion.
No whole-cache flush/finalizer/reset/switch/join, firmware borrowing, callback
removal, pending clear, native GPU grant or event/service suppression.
