# Reference retirement after preservation

241 proves bounded pixel preservation at one pinned Xromwell entry. Its existing finish function restores old producer admission on success. Therefore it does not establish a persistent closed-admission handoff, complete reference disposal or native ownership. The next experiment must distinguish these transitions explicitly.

First add a finite post-preservation observation within the SAME stopped-entry intervention, while admission remains genuinely closed. Record actual queue/parser/waits/frontend state, dirty flags, range identities and bindings/callbacks before and after. Keep refusal/timeout publication immutable and quarantine unsafe outcomes. Do not reuse or reset the238 one-shot observer: new slots need separate ownership and publication records. Sampling different boots cannot prove retirement.

Build the reference inventory from actual compiled paths before disposing anything. It must cover color/zeta surfaces, overlapping surface aliases, surface access callbacks, texture cache references, draw/shader/vertex state and display-context references. Every observed reference needs a defined owner, a disposal operation and a completion condition. A null renderer pointer is not proof that another thread or queued callback has released its reference.

Pinned surface.c unregister_cpu_access_callback calls mem_access_callback_remove_by_ref; the primary physmem implementation queues removal through async_safe_run_on_cpu. The retirement design must account for CPU work completion while the guest is stopped, rather than claiming completion when the surface's access_cb is cleared. Never wait for a callback or another worker while holding FIFO, PG, renderer or BQL locks if that actor can need those locks. Actual ordering and bounded failure handling require a new reviewed diagnostic, not an assumption that asynchronous removal is immediate.

Preserve dirty pixels before any invalidate/flush operation. Existing flush_surfaces has a disabled dirty-download call; never use its list removal as preservation evidence. Retain conflicting aliases as failures until the latest content owner is established. Ordinary texture/shader/display destruction must use its own defined GL context/worker ownership and must not operate on references still exposed to another actor.

Only after actual producer closure, fence/readback, all-reference retirement and completion are proved may a distinct native ownership token be considered. The native224 workload currently refuses UNMODELED_BUSY/NO_OWNERSHIP, correctly. Do not convert the host's successful preservation counter into that token or expose an accelerated allocator merely because the list is empty. Require reproducible emulator correctness/cold checks and a separate physical comparison with rollback before performance or hardware claims.
