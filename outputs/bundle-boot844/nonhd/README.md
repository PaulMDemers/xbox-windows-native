# Non-HD 1024x576 E candidate

The guarded 004 chain is a source-only adaptation of the earlier physical 0093 non-HD profile. It uses the independent 843 FATX build and the original non-HD video driver and boot-video provider. It has not been tested on physical hardware. The boot guard requires 64 MiB, a Conexant encoder response, the widescreen EEPROM bit and a composite, S-video or SCART AV branch; HDTV, VGA and unknown cable types stop before scanout setup. The historical physical cable was not independently recorded. Only the composite branch was exercised in these emulator tests.

The physical F-snapshot SYSTEM hive was adapted to E by swapping four E/F volume identities; semantic comparison found no other registry changes. A valid 4096-byte video trace remains required. The candidate package contains private Windows files and user profiles and must remain private. Its complete E file and directory manifest matches the input used by run016, as recorded in `package-comparison016.json`.

- Run013: the F-derived E image with historical FATX0088 reached the Windows desktop; emulated keyboard and mouse actions worked on a one-cluster root.
- Run014: the same F-derived image with a synthetic two-cluster E root and WINNT in the second cluster stopped with 0xA using FATX0088. Preboot allocation audit passed.
- Run015: the matched two-cluster control with the fixed FATX843 driver reached the desktop and accepted emulated keyboard and mouse actions. Preboot allocation audit passed. See `qualification015.json`.
- Run016: an independent fresh one-cluster F-derived E input with FATX843 reached the desktop and accepted keyboard and mouse actions. See `qualification016.json`.

These were snapshot boots. They do not demonstrate a normal shutdown, durable writes, a post-boot allocation audit, extensive storage safety or physical E operation. A Found New Hardware wizard remained visible. Earlier mixed stock-E controls 006, 008, 009 and 011 failed and remain failures; 007 and 010 reached a desktop under their separate control conditions. One passing pair does not establish reliability.

`build004.json` and `host-test004.json` retain source-tree, tool, artifact and guard-test pins. Complete build records and screenshots remain private. The separately prepared 0.1.0 file snapshot is a pre-0093 physical F input, not a byte-identical capture of the later 0093 installation. Source reconstruction does not imply byte-identical rebuilding of every historical component.

Rebuilding: `rebuild004.py` is a portable adaptation of the exact executed build script; the path-parameterized adaptation itself has not been run as a complete rebuild. Set `XWN_BUILD_LEASE=held` only under the shared build lease, and set `XWN_BUILD_DIR` and `XWN_OUTPUT_DIR` to new, non-existing directories, `XWN_REPLAY_SOURCE` to the independently reconstructed source checkout described in `outputs/video-trace-reuse/inputs.json`, `XWN_CROMWELL_SOURCE` to the pinned Cromwell checkout, `XWN_ROSBE` to the pinned RosBE installation, and `XWN_FIXED_FAT_SOURCE` to the independently reconstructed 843 `fat.c` (its SHA-256 is checked by the script). Required existing repository patches and tool hashes are verified by the script. Run in Linux with the expected compiler and build tools. `test-guard004.py` takes the same build and output directory variables plus a new `XWN_TEST_OUTPUT`; it compiles a guard test and checks the built XBE path. `rebuild-f-hive.py` takes `XWN_HIVE_SOURCE` and a new `XWN_HIVE_OUTPUT`, with Python hivex installed; its output and report are private. The original executed scripts and full reports remain private, with script hashes in `private-script-pins.json`.
