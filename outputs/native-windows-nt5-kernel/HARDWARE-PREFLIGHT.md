# Physical Xbox test prerequisites

The v2 hardware inventory completed on Paul's physical Xbox on 3 October 2026. All twelve selected PCI reads returned, the log reports success, and Paul reports visible operation. The Windows desktop and driver milestones remain emulator results; Windows kernel entry is now confirmed on this console; a complete Windows boot and desktop remain unachieved. The inventory wrote only its app-local diagnostic file.

## Confirmed physical baseline

The supplied [physical report](../native-windows-hardware-probe-v2/evidence/physical-v2-complete.txt) records 64 MiB RAM, kernel 1.0.4034.1, GPU revision 163, MCPX revision 178, a 640x480x32 display at 60 Hz, and framebuffer physical address 0x03eb4000 after nxdk initialization. ELCR 0x1800 and LPC routing 0x0e065491 match the emulator inventory. The USB controllers, Ethernet and GPU also match the emulator's principal MMIO addresses and IRQ lines. See [the recorded comparison](../native-windows-hardware-probe-v2/physical-validation.json) for all header differences.

V1 stopped immediately before a read of the known-dangerous PCI address 00:00.1. V2 excludes that address and 00:00.2, limits reads to known targets, and flushes progress markers. The successful v2 run supports that diagnosis; no more inventory rerun is needed with the current setup.

## Differences that affect the first Windows test

The physical audio controller exposes I/O BARs at 0xd000 and 0xd200 in addition to MMIO at 0xfec00000. The experimental ac97xnt5 resource validator requires zero translated port descriptors and would reject a resource list containing those ranges. Codec behavior also remains unvalidated. Leave this driver disabled for the first physical Windows test; audio needs a separate hardware-specific pass.

The real memory controller is 10de:02a6 at 00:00.3, where xemu exposes 1b36:0005. IDE programming-interface data and AGP bridge configuration also differ. These are recorded differences, not evidence of defective hardware. Do not copy the emulator bridge configuration onto this console.

The physical Xromwell-to-FreeLoader discovery diagnostic now reaches XWN40 with visible output. The [console photo](../native-windows-physical-loader/evidence/physical-after-reboot/physical-xwn40.jpg) shows the same seven discovery descriptors as the emulator, covering 64 MiB with the upper 4 MiB marked firmware-permanent. This confirms visible loader output and its reported reservation; it does not validate the final NT memory map or Windows display driver. The display miniport has no acceleration or mode switching.
