# Next controlled investigation

The serial boundary and append-sequence controls plus first-install and actual
warning-alignment diagnostics provide bounded negative reproduction evidence.
Do not interpret them as a repair, proof of power loss, or clearance of the
physical111-byte anomaly. Preserve original damaged bytes and strict failures.

The next useful variable is concurrent activity during the write, rather than
more identical quiet boots. Prepare paired fresh emulator fixtures from the same
qualified parent: a no-drawing control and a bounded user-mode GDI drawing worker
alongside known-source append/flush workloads. Keep source hashes, API results,
completed byte counts, deterministic filenames and cold expected-byte oracle.
Use only an owned window and ordinary supported APIs, no direct framebuffer or
register writes. Retain the current FATX0101/video0093 binaries. Keep driver
instrumentation, debugger changes, reset injection and device-policy changes out
of this comparison. Drawing changes timing, so this would be a load diagnostic,
not a video-performance benchmark or physical qualification.

The real installer path can then be examined under that same bounded load only
if the control is well-defined. Exact source/cold bytes are available for the
synthetic writer, whereas an intact final SetupAPI line does not observe its
original live caller buffer. Do not conflate these evidence classes.

If a mismatch recurs, preserve the failed disk and map logical offset to the
actual FAT chain, controller LBA, source bytes and completion/flush history before
editing the driver. If it does not, report the original anomaly unresolved.
The first physical reboot method remains an unanswered optional clarification;
absence of EventLog6006 does not establish a power interruption. A separately
labelled interrupted-shutdown diagnostic would require a new owned fixture and
must never be promoted to an ordinary persistence pass.

Physical unattended qualification still needs explicit handling of the actual
remaining devices and the reserved/raw-C capacity warning. Do not reinstall the
working GPU, suppress global warnings, remove shadowc.img, or transplant xemu's
placeholder-device policy onto hardware. Preserve all rollback/v0.1.0 artifacts.
No physical launch is included in these emulator diagnostics.
