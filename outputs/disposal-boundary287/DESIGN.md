# Current objects, historical anchors and actual-provider obligations

X287Proof holds immutable original anchors separately from current owner tuples.
Anchor refcounts describe the attested INITIAL state only; no current absent
object is represented by a fabricated positive refcount. Original allocation,
source, opaque key and original generation remain fixed across the chain. The
actual provider must derive anchors once from current live cache edges under
the full admitted owner/context/CPU proof and native allocations.

Stage1: all current owners equal anchors, refs2/cache1/unit1. Stage2: same live
owners refs1/cache1/unit0, in BOTH modes. Stage3 control remains cache-only;
candidate has no old current owner, key, refcount, edge or live namespace value.
Stage4 control rebinds old generations; candidate uses actually observed new
creation/bind generations5..8 with matching keys and refs2/cache1/unit1. An old
numeric pointer/name can reappear only with a new generation and earlier verified
absence. Historical old_gl_deleted at stage4 refers to the stage3 fact; it is
not a claim that the recycled numeric name is still absent from current GL.

All current keys and guards must match independently owned original bytes. Raw
identity/name changes at stage4 may be valid and therefore require joining the
actual284/285/286 creation record; the scalar validator alone cannot authenticate
a supplied replacement. Likewise complete known GL4.0/context/container/UI graphs
must establish absence, no hidden selected bindings and unchanged unrelated
owners. Model booleans must never be copied into a production proof as authority.

Common checks preserve actual-owner identity, distinct native contexts, stopped
CPU/closed frontend, halted/drained FIFO, pending/error refusal, finite fences,
fresh CPU epochs1..8 and complete callback/surface bijection. Whole allocation
blocks remain disjoint even when their selected texture object is absent. First
three boundaries require identical callback tuples/surfaces and mutation clock;
after guest work the new pair must be internally stable and the global clock
cannot move backward. Time/context/immutable-anchor continuity stays explicit.

The actual worker must preallocate four immutable ledgers and acknowledge fresh
CPU pairs for each. Unit release and original283 LRU final disposal occur once,
on the original renderer owner with exact live proof and context checks. Complete
post-disposal graph/snapshots BEFORE guest resume. Partial mutation, namespace,
snapshot, transport, publication or deadline failure quarantines with exact masks;
no rollback/refcount assignment/forced completion. Overall acquired transaction
state, not one completed slot, controls reads and resume.

No collector, worker orchestration, independent full transport or actual runtime
provider is implemented in287. Existing templates are source leads, not permission
to bypass remaining evidence. Native Windows PTE/cache aliases and deferred
release remain separate from this narrow emulator-owned texture experiment.
