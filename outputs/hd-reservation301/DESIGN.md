# Matched ordinary Windows test on the HDTV connector path

Each case starts from the same never-executed combined251 preparation. Five files are replaced together: relocated Cromwell, FreeLdr, rosload, bootvid and miniport.300control/candidate differ only by the reservation profile; audio004, software display118, FATX0101 and startup workload remain unchanged. The compiled binaries and all prepared file hashes are pinned. Each independent preparation is flattened and compared before use; no completed runtime is a parent.

Both cases explicitly select the emulated HDTV AV connector and the previously pinned HD-enabled private EEPROM. This adds a matched control for that branch, which296's composite profile did not cover. Cromwell still programs its original low-resolution HDTV mode; neither case requests1080i. The native Windows dimensions are measured from the workload rather than assumed.

The existing bounded audio/drawing runner, event delta checks, structural hive checks, allocation audit and independent PCM channel/silence classifier are retained. One SITE EXEC per case, no debugger, no repeat launch after a lost reply. A guest normal restart and dashboard return precede orderly host stop/quit and cold collection. Original strict events remain failures even if the narrow workload passes. Private roots/portable/scratch are on D; all existing disk parents stay in place.

This ordinary test can demonstrate boot/drawing/audio/integrity on the new chain, but separate runtime evidence is still needed for exact reserved PFNs, actual shared-view mapping/cache attributes and hidden-buffer boundaries before physical or1080i promotion. User TV reports from297/298 are standalone kernel tests, not evidence from this emulator pair.
