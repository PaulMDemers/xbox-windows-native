# Independent physical-buffer observation

This NEW disposable child uses the unchanged ordinarily qualified0108 display
and the same sharedUC/storage/network stack. No physical-console access occurs.
The new probe parks the pointer outside its window and reports twelve exported
boundaries before/after two copy paths, at64x64 and768x384. It obtains real client
coordinates via ClientToScreen. All ordinary54case/162stage checks and54driver
self-checks still run, with unchanged cold/event gates; timings are diagnostic.

The observer uses a600second bound and a single probe breakpoint. At each stop
it checks exact phase order, the actual probe process/module/header/resident
bytes, and actual loaded xwnram/kernel identities with relocation-safe code pins.
It saves the physical03c00000 framebuffer directly through the emulator monitor
and compares every RGB pixel in the expected rectangle with an independently
computed pattern. This does not use a driver-returned copy or GDI readback.
It covers initialization, DIB-to-primary and overlapping-primary-copy visibility,
not the fourteen rendering interfaces, pointer exclusion or all scanout modes.

All breakpoints are removed and the guest resumed even on observer failure.
The observer must be armed before the supervisor issues its one launch command.
Normal shutdown/dashboard and full cold audit follow. Debugger results remain
separate from the prior ordinary matched pair; no physical performance claim.

The initial probe compile failed Werror misleading-indentation on a one-line
cursor check. The exact source is retained in probe-build-failure001. Braces and
a separate record statement fixed that host compile; no guest had launched.
