# Larger drawing-area discriminator

The closed315/324 tests measured the same256x128 area at720p/1080i and do not explain large-window repaint cost.327 varies the affected area on the unchanged release driver. It deliberately does not change framebuffer cache attributes, GPU ownership or drawing implementation.

Each supported size allocates two top-down32-bit DIBs, with client width/height48 pixels greater than the operation dimensions. Both source and destination rectangles lie within a16-pixel outer guard around their union. The largest pair is4,741,632bytes; original small probe allocations remain live. Allocation or visible-client failure is a test failure, not an instruction to shrink the test automatically.

Source RGB channels are independent linear patterns modulo256; source alpha is anA5 sentinel. The expected overlap result walks the inverse copy coordinates for each completed operation. The host oracle instead saves whole forward-copy source rectangles before writing their destination and compares every pixel. Display readback compares RGB; source DIB validation also requires the alpha sentinel. This distinguishes permissible display alpha handling from corruption of source storage.

Each operation loops until at least750ms or20,000 operations. Successful intervals require1..20,000 operations and750..30,000ms. The outer runner's existing180-second per-process watchdog still bounds stuck GDI calls; individual Win32 drawing calls are not cancellable. There are15 intervals, with an11.25-second minimum total excluding the original tests,30 statistics snapshots and all correctness readbacks. Worst-case accepted interval bounds exceed the runner watchdog; that watchdog takes precedence and no slow run should be silently accepted by extending it. Actual completion time must be established in the emulator first.

Repaint uses an explicit invalidated interior rectangle and the real WM_PAINT handler, requiring one completed paint per iteration. Every operation flushes, pumps messages and revalidates the unobscured client rectangle. These checks are included in elapsed time. Resizing, allocation, seeding, readback, logging and counter snapshots are excluded. Independent before/after packet parsing refuses saturated or decreasing counters even if application completion is present.

The327 parser enforces exact extension ordering, all32 values in each packet, geometry and memory lengths, both pixel checks, timings, repaint counts, computed counter deltas and terminal coverage. Legacy206 parsers remain independent requirements. No benchmark timing is qualified until the ordinary runtime, normal restart, current event deltas and complete cold audits pass their existing gates. Emulator timing must not be presented as physical performance.

No327 runtime harness is frozen yet. Before one is used it must preserve the existing joined helper/audio/setup checks, build/xemu leases, immutable seed/source pins, unique runtime IDs, no-retry launch records, bounded observer, orderly host exit and complete cold readback. The longer combined budget must be explicitly reviewed alongside the existing per-probe watchdog rather than copied inconsistently from323.
